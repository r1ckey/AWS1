AMIとインスタンス起動

  • AMI (Amazon Machine Image): OSやアプリを含むサーバーのテンプレート
  • 起動プロセス: AMIを選択し、インスタンスタイプやNWを構成
  • カスタムAMI: 自分の構成を保存して、同じサーバーを即座に複製可能

EC2を起動するには、まず「テンプレート」となるAMIを選び、ストレージ（EBS）を定義します。

インスタンスタイプ

  • 命名規則: ファミリー + 世代 + サイズ (例: t3.medium)
  • T系: バースト可能（安価、小規模Web用）
  • C系: コンピューティング最適化（バッチ、計算用）
  • M系: 汎用（バランス型）
  • R系: メモリ最適化（DB、インメモリ用）

EC2には膨大な種類のサイズ（CPUやメモリの組み合わせ）があり、用途に最適な「タイプ」を選択することで、コストとパフォーマンスのバランスを取ります。

  • T3/T3a: 普段は低い負荷で、必要時だけ性能を上げる（バースト）。開発環境に最適です。
  • C6g: AWS設計のGraviton2プロセッサを搭載。高いコスパを誇ります。

※試験では「コンピューティングならC」「メモリならR」というキーワードの紐付けが重要です。

EBS (Elastic Block Store)

  • ブロックストレージ: EC2にアタッチして使うハードディスクのような存在
  • ライフサイクル: インスタンスを停止してもデータは保持される
  • スナップショット: ポイントインタイムのバックアップ（S3へ保存）

EBSは、ネットワーク経由でEC2に接続される仮想ディスクです。特徴は、物理的なドライブと違い、容量を動的に増やしたり、性能（IOPS）を変更したりできる点にあります。

  • GP3 (汎用SSD): 最も推奨される。コストと性能のバランス。
  • IO2 (プロビジョンドIOPS): 非常に高いI/Oが必要なDBなどで使用。

ユーザーデータとブートストラップ

  • ブートストラップ: 起動時に自動で設定スクリプトを実行
  • ユーザーデータ: 起動時に渡すシェルスクリプトなど
  • 初回のみ実行: 基本的にインスタンスの「最初の起動時」に1回だけ動く

新しいサーバーを立てるたびに手動で「yum install httpd」などを打つのは非効率です。ユーザーデータフィールドにスクリプトを記述しておけば、起動直後に自動でアプリケーションのインストールや設定を完了させることができます。
