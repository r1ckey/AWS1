RDS (Relational Database Service) の基本

  • マネージドサービス: OSレベルのパッチ、バックアップをAWSが代行
  • 対応エンジン: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server
  • バックアップ: 自動バックアップ機能により任意の時点に復元可能

RDSは、セットアップ、運用、スケールを簡単に行えるリレーショナルデータベースのマネージドサービスです。EC2上に自前でDBを構築する場合と異なり、OSの管理やミドルウェアのセットアップをAWSに任せられるため、開発者はアプリ開発に集中できます。

高可用性 (Multi-AZ)

  • 配置: 異なるAZ（可用性ゾーン）にスタンバイ機を配置
  • フェイルオーバー: プライマリが故障した際、自動で切り替わる
  • 同期複製: データは常に両方のAZに書き込まれる

ミッションクリティカルなシステムでは、Multi-AZ構成が必須です。プライマリDBがダウンした場合でも、DNSの書き換えにより数分以内で自動的にスタンバイDBが昇格し、エンドユーザーへの影響を最小限に抑えます。これはあくまで「高可用性」のための機能であり、パフォーマンス向上用ではありません。

Amazon Aurora

  • AWS設計: クラウドネイティブな超高性能データベースエンジン
  • 高速・堅牢: MySQLの5倍、PostgreSQLの3倍のパフォーマンス
  • データ分散: 3つのAZに計6つのコピーを保存する特殊ストレージ

Auroraは、AWSがクラウド向けにゼロから設計し直した、可用性とパフォーマンスに特化したエンジンです。最大15個のリードレプリカを作成可能で、大規模なトラフィックにも対応できます。ストレージは自動で拡張され、管理の手間が大幅に軽減されます。

リードレプリカ

  • 目的: 読み取り負荷の分散によるパフォーマンス向上
  • 方式: 非同期複製（プライマリからデータをコピー）
  • 範囲: リージョンを跨いだ配置（クロスリージョン）も可能

ウェブサイトの閲覧など、参照系のリクエストが多い場合に、読み取り専用の複製（リードレプリカ）を作成してメインDBの負荷を逃がす手法です。Multi-AZと違い、データのコピーは「非同期」で行われるため、わずかなラグが生じる可能性がある点に注意が必要です。
